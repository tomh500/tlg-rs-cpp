# 从 OI 到图像编解码

这份代码围绕三个可单独理解的算法展开：模 256 差分、滑动窗口字符串匹配、预测残差的游程与自适应 Golomb/Rice 编码。公开接口只接收紧密排列的 Gray/RGB/RGBA 字节；文件内部的 BGR 变换由编解码器处理。

## TLG5：二维差分与可逆变换

令当前像素通道为 `p(x,y)`，边界外像素为 0。先做垂直差分 `v(x,y)=p(x,y)-p(x,y-1)`，再做水平差分 `d(x,y)=v(x,y)-v(x-1,y)`。所有运算都在 `Z/256Z` 中完成：转换到 `uint8_t` 的环绕是格式的一部分。

RGB 残差写成 `(B-G), G, (R-G)`，alpha 保持独立。解码顺序相反：还原颜色差分，沿行累加，再加上上一行。每个通道在一组行内形成独立的平面，由 Slide 压缩；压缩后不够小则直接写原始平面。

一个关键不变量是：**只有实际写入的压缩平面推进 Slide 字典**。编码器先保存状态，若选择原始平面则恢复；否则下一平面会使用解码器不知道的历史数据。解码端用输入 `span` 直接引用原始平面，避免无意义的复制。编码器块高为 4，解码器支持任意正块高。

## Slide：环形数组与哈希链

字典大小 `W=4096`，最长匹配 `M=273`。3 字节键映射到 32768 个桶，`heads` 指向最新候选，环形 `previous` 数组连接同桶的旧候选。用绝对位置判断候选是否还在窗口里，避免环形下标相等造成歧义；计数接近上限时统一重定位。

编码一组最多 8 个 token：一个标志字节说明各 token 是字面量还是字典引用。引用存储 12 位字典位置和长度；长度达到 18 后用第三字节扩展。解码按字节前进，因此允许重叠复制。例如距离 1 的匹配可以重复刚写出的字节。这让长重复串在一个字面量之后即可压缩。

候选探测先比较已知最佳长度处，再用 `memcpy` 读取完整落在匹配边界内的 8 字节，并用 XOR 与 `countr_zero` 查第一个不同字节。`memcpy` 允许未对齐读取，也遵守 C++ 别名规则。尾部不足 8 字节时逐字节比较。

哈希链是加速候选搜索，不是改变最坏情况的魔法。形式上的上界是 `O(NWM)`；固定窗口下通常接近线性。内存为 `O(W+H)`，`H=32768`。不要把平均表现写成无条件的 `O(N)` 保证。

## TLG6：8×8 分块、预测与熵编码

每个块尝试 MED 和向上取整的 AVG 两种预测。MED 取左邻 `a`、上邻 `b`、左上邻 `c`：若 `c≥max(a,b)` 取较小值，若 `c≤min(a,b)` 取较大值，其余取 `a+b-c`。这种分段预测能保留水平和垂直边缘。

RGB 再尝试 16 种可逆颜色变换；Gray 只需要一种，RGBA 的 alpha 不参与颜色变换。候选成本包含每个参与通道和 alpha 的编码估计。块内成本与整条块行的真实自适应状态不同，因此这是局部启发式，不保证全局最小文件。

残差按蛇形顺序排列：奇数列块纵向翻转，奇数图像行横向翻转。编码和解码共用同一索引公式，让不足 8 行/列的边缘块也保持双射。

熵编码先交替记录零/非零游程长度，长度用 gamma 编码；非零有符号字节映射成无符号值后用 Rice 编码。参数 `k` 由格式指定的表和累计残差状态更新。TLG6 的长商逃逸以当前字节位置为基准，不能替换成一般的固定长度 unary 规则。

实现先确定全图的块滤波表，再用第二遍输出压缩数据，避免同时保存一整幅额外压缩结果。辅助存储为滤波表 `O(ceil(w/8)ceil(h/8))` 和最多 8 行的残差 `O(w)`，另外包含结果文件和最终图像本身。输入像素是借用视图，不需要复制。

实现中的通道数分派在块外完成，让编译器展开固定布局。x86-64 上利用基线 SSE2 并行处理同一像素的多个通道，其他目标使用逐字节隔离的整数运算。`TLG_ENABLE_SIMD=OFF` 可强制验证可移植路径。优化只改变计算方式，输出仍遵守相同的模 256 算法。

## 解析也是算法的一部分

SDS 的元信息格式为 `keyByteLength:key=valueByteLength:value,`。逗号、冒号、等号可以出现在内容中，所以必须按字节长度消费，不能用分隔符拆分。键按序存储使编码输出可复现；重复键报错，未知 SDS 扩展块按其长度跳过。

每次读取由当前输入范围限定，TLG5 通道还受块长度限定，TLG6 位读取受声明位长限定。解码先验证尺寸乘法、像素和字节上限，再分配图像。游程与 Slide 引用必须准确填满目标缓冲；截断、超出目标、未消费的数据都会成为结构化错误。
