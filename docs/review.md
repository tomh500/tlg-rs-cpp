本次审查从 C++ 初版提交 `d0ac8bf` 出发，检查 TLG5/TLG6、Slide、SDS、公开 API、
文件与命令行操作、CMake 接入和性能测量。以下问题已修复，并补充对应验证。

| 优先级 | 问题与复现 | 修复与验证 |
|---|---|---|
| P1 | 28 字节 TLG5 声明 1 MiB 灰度图，块大小为零，尚未检查通道头就尝试申请 1,048,615 字节。TLG6 的缺失熵块、无效 Slide 滤波流和超限 SDS 也会过早申请图像或解压缓冲。 | TLG5 先检查全部块和 Slide token；TLG6 先检查全部熵块长度；Slide 先核对完整 token 流；SDS 先检查扩展块和元数据限额。独立分配预算测试覆盖这六种输入，修复前首例失败，修复后通过。 |
| P2 | `auto view = tlg::Image{...}.view();` 在语句结束后留下悬空像素视图。 | `view()` 仅允许左值对象，删除右值重载；编译期检查确认可借用普通和 const 图像，拒绝临时对象。 |
| P2 | 1×1 RGBA 基准将解码毫秒数格式化成 `0.000`，比较脚本输出 `Infinity` 或 `NaN`。 | C++ 和 Rust 驱动保留浮点精度，拒绝时钟分辨率不足的测量；比较脚本按 invariant culture 读取耗时并拒绝零值、负数与非有限值。修复后六组微小图像均得到有限倍率。 |

`ImageView` 的所有者仍须在使用视图期间存活。结构检查可以提前拒绝缺失块、
错误长度和无效 Slide 流；完整的 TLG6 残差码语义仍在解压时检查。图像尺寸与
配置的资源限额继续约束合法大图像的内存使用。

## 验证结果

- MSVC Release、Debug、ASan RelWithDebInfo、ASan Debug 和关闭 SIMD 的 Release：每种配置五项 CTest 全部通过。
- 原 Rust 与当前 C++ 的 24 项双向格式、尺寸、布局和像素检查全部通过；不可变样本继续覆盖 SDS 和全部 32 种 TLG6 filter/predictor code。
- 审查用 ASan 突变程序对 144 个格式、布局、尺寸、数据模式和 SDS 种子进行 150,000 次输入突变：3,149 个仍合法，146,851 个拒绝；成功结果经重新编码、解码验证像素和元数据，失败结果检查错误说明与字节位置。
- 将 Slide 内部绝对位置平移到重定位阈值，覆盖冷字典、完整字典、重复与随机内容及 store/restore，252 项 token 和字典状态检查通过。
- Debug ASan 应用通过 `add_subdirectory` 链接并运行；安装后独立应用通过 `find_package(tlg)` 编解码通过。未复现所怀疑的 Debug `/RTC1` 冲突。
- 六组 512×512 RGBA 性能已重新测量，原始数据、计时精度与额外验证成本见 [基准记录](benchmark.md)。

常规验证可通过 [测试说明](../tests/README.md) 的 CMake/CTest 与互操作脚本重跑。
